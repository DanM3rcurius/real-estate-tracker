´´´bash
python scripts/backup_db.py     # → backups/hofradar-<timestamp>.db
hofradar migrate --check        # exits 1 while pending
hofradar init-db                # migrates + registers sources
hofradar serve                  # Ctrl-C to stop
´´´

### delete proptry script
it was built, dry-run is the default — you don't pass a flag for it, you pass --apply to actually delete. There's no --dry-run/--dryrun flag. Confirm the exact syntax with:

hofradar delete-property --help

Then to find a real public_id to test against — probably that "Merkliste" junk row from issue 
#10
 is a good candidate to verify against. A few ways to find its ID:

Look it up in the web UI (the dossier page shows the public_id, something like hof-XXXXXXXX).
Or from the CLI/DB directly:
sqlite3 data/hofradar.sqlite3 "SELECT public_id, canonical_title FROM properties WHERE canonical_title LIKE '%Merkliste%';"

Once you have the real ID:

hofradar delete-property hof-XXXXXXXX

(no --apply → just prints what it would delete — the dependent row counts — as a dry run)

hofradar delete-property hof-XXXXXXXX --apply

(actually deletes, with a backup taken first)

Paste the --help output if the flags don't match what I described — I built this from the implementer's report, not a live check against your running install, so worth confirming before you run --apply.
